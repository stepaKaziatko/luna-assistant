# Задача по циклу в одном чате

Запрос: `$ARGUMENTS`. CLI `clab` должен быть вошедшим (`clab auth status`),
MCP-сервер проекта — подключённым (`clab mcp install`). Проект берётся по
`git remote` текущего каталога; если каталог не репозиторий проекта, все
команды запускать с `SDLC_PROJECT=<КЛЮЧ>`. Порядок работы одной роли —
скил `clab-work`.

Этот чат — **оркестратор**. Он не делает работу ролей сам: читает состояние
задачи, на каждый этап запускает саб-агента ролью статуса, принимает его
отчёт, спрашивает человека там, где цикл требует апрува, и двигает переходы,
которые не требуют работы роли. Так задача проходит цикл от бэклога до
терминального статуса, не покидая чата.

Аргумент `до <статус>` останавливает проход, когда задача встала на этот
статус. Без него — до терминального.

## Цикл оркестратора

Повторять, пока задача не дошла до цели:

1. **Прочитать состояние.** `clab show <ключ> --json` — статус, роль этапа
   (поле `role`; его нет — на статусе никто не работает), гейты впереди.
   `clab gates <ключ> --json` — по каждому переходу `allowed` и гейты со
   статусами.
2. **Терминальный статус или статус из `до`** — закончить (шаг «Итог»).
3. **На статусе нет роли** (бэклог): ровно один переход `advance` с
   `allowed: true` — выполнить его: `clab transition <ключ> --to <переход>
   --summary "взято в работу из чата"`. Запуск задачи — решение человека,
   и он его уже принял, попросив взять задачу. Переходов несколько —
   спросить, каким идти.
4. **Переход ждёт только человека**: у перехода `advance` все блокирующие
   гейты `passed`, кроме `human_approval` со статусом `pending` —
   **спросить апрув в чате** (раздел «Апрув»). После `passed` выполнить
   переход: `clab transition <ключ> --to <переход> --summary "апрув в чате"`.
   Если рядом ещё не прошёл гейт, который закрывает роль (артефакт не сдан,
   PR не привязан), — сначала шаг 5.
5. **Иначе на этапе есть работа роли** — запустить саб-агента (раздел
   «Саб-агент»), дождаться отчёта, вернуться к шагу 1. Отчёт пересказать
   человеку в две-три строки: что сдано, какой переход запрошен, что мешает.
6. **Возврат** (саб-агент запросил переход-возврат с артефактом-проблемой) —
   штатный ход: следующий круг запустит роль предыдущего этапа, она увидит
   проблему во входных артефактах. Считать круги.

**Предохранители.** Больше восьми запусков саб-агентов за проход или третий
заход роли на тот же этап — остановиться и спросить человека, продолжать ли
и что поменять. Саб-агент отчитался, а состояние задачи не изменилось
(переход не запрошен, артефактов не прибавилось) — не перезапускать молча:
показать его отчёт и спросить. Саб-агент сообщил вопрос человеку — задать его
через `AskUserQuestion` и перезапустить роль с ответом в промпте.

## Саб-агент

Один саб-агент — один заход роли на этап. Запускать тулом `Agent`
(тип `general-purpose`, не в фоне — следующий шаг зависит от отчёта),
`description` вида `<ключ>: <роль>`. Промпт:

```
Ты — роль `<роль>` на этапе `<статус>` задачи <ключ> проекта <КЛЮЧ ПРОЕКТА>
в Cadence Lab. Рабочая директория — <путь>, CLI `clab` вошёл, команды
запускать с SDLC_PROJECT=<КЛЮЧ ПРОЕКТА>, MCP-сервер проекта подключён.

Вызови скил `clab-work` тулом Skill с аргументами `<ключ> <роль>` и выполни
его от начала до конца: забери этап, прочитай контекст и входные артефакты,
сделай работу роли по её инструкции из ответа захвата, сдай артефакты
контракта, отчитайся о стоимости и запроси переход. Инструкция роли главнее
всего остального.

Ограничения:
- Ты работаешь без человека: тулом AskUserQuestion не пользуйся. Нужно
  решение человека — не гадай, напиши вопрос в отчёте и остановись.
- Код и проверки — только в рабочей копии задачи `.worktrees/<ключ>/<репо>`;
  основные копии репозиториев стоят на main, их не трогать.
- Область задачи не расширять, задачу силой не двигать. Не получается —
  артефакт-проблема и переход-возврат, как велит скил.
- Этап закончить одним из двух: переход запрошен (`clab transition`) либо
  задача отпущена (`clab release <ключ> --note "…"`). Гейт human_approval
  закрывает человек — запросить переход и остановиться, не ждать.
<дополнительный контекст: причина отказа человека, ответ на вопрос, номер круга>

Отчёт (последнее сообщение, только он вернётся оркестратору):
1. Что сделано — три-пять строк по делу.
2. Сданные артефакты: kind и заголовок каждого.
3. PR и ветки, если есть: репозиторий, номер, ссылка.
4. Запрошенный переход и его результат: прошёл / что мешает по `clab gates`.
5. Вопросы человеку, если есть.
6. Стоимость: модель, токены, оценка в долларах — то, что ушло в `clab usage`.
```

Роль берётся из поля `role.key` ответа `clab show`. Саб-агент работает от
имени того же вошедшего человека, что и оркестратор, поэтому аренда,
оставшаяся от предыдущего захода, ему не помешает.

## Апрув

Гейт `human_approval` закрывает только человек, и это — единственное, что
оркестратор спрашивает по ходу цикла. Вопрос должен быть коротким и
достаточным, чтобы ответить не выходя из чата: **что конкретно
утверждается** — три-пять строк по артефактам этапа (после аналитики —
какие части и в каком порядке будут сделаны, что не входит; перед слиянием —
PR со ссылками и состоянием, что проверил тестировщик) — и **ссылка на
карточку задачи** для подробного изучения. Заголовки артефактов —
`clab show <ключ> --json`, поле `context.prior_artifacts`, содержимое —
`sdlc_get_artifact`.

Спросить тулом `AskUserQuestion`, один вопрос, варианты:

- **Апрув** — `clab decide <ключ> --transition <переход> --gate
  <ключ гейта> --status passed`, затем переход.
- **Вернуть с замечанием** — человек пишет причину в «Other»; `clab decide …
  --status failed --details '{"reason":"…"}'`, и следующий круг запускает
  роль этого же этапа с причиной в промпте (задача остаётся на статусе,
  переход-возврат не нужен).
- **Остановиться** — закончить проход, задача ждёт апрува в карточке.

Ключ гейта и переход брать из `clab gates --json`, не из памяти.

## Итог

Когда задача дошла до цели или проход остановлен — короткий отчёт: где
задача, какие этапы пройдены и сколько заходов было, PR и ветки, что ждёт
человека, суммарная стоимость из отчётов саб-агентов.

## Не делать

- Не делать работу роли в этом чате: артефакты сдаёт саб-агент. Оркестратор
  правит только переходы без работы роли и решения человека.
- Не ставить апрув без явного ответа человека в этом чате и не пропускать
  `human_approval` переходом-обходом.
- Не вести в одном чате две задачи: одна задача — один проход.
