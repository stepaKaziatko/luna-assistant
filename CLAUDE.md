# CLAUDE.md — Luna

Нативное macOS-приложение в вырезе MacBook: показывает сессии ИИ-агентов, даёт подтверждать их запросы и отвечать на вопросы из острова, чат с моделями, интеграции, голос. Код — перенесённый [coucou](https://github.com/Louis-CFM/coucou) (см. [assistant-project.md](assistant-project.md)); запуск и разрешения macOS — [README.md](README.md).

## Где что лежит

| Путь | Что там |
|---|---|
| `apps/macos/project.yml` | Проект для XcodeGen. `Luna.xcodeproj` и `Resources/Info*.plist` из него генерируются и коммитятся; руками не правятся |
| `apps/macos/Sources/App/` | Mac: остров (`IslandWindowController`, `IslandViewContent`, `IslandStateMachine`), хуки агентов и генерируемые плагины (`HookServer.swift`), интеграции (`*Poller.swift`, `*Controller.swift`), настройки, `Voice/` |
| `apps/macos/Sources/LunaKit/` | Общее с iPhone: персонаж (`BotEngine`, `LunaStill`, `LunaWardrobe`), `PillCatalog.swift` — единственный источник правды о pill (ID, цвет, категория), diff, модели |
| `apps/macos/Sources/Phone/`, `Widgets/`, `NotificationContent/` | iPhone-таргеты. Переносятся как есть, не собираются (нужны команда Apple Developer, CloudKit, relay) |
| `tests/`, `scripts/test-*.sh` | Тесты на `swiftc`: скрипт собирает нужные файлы и запускает проверки |
| `docs/` | `USER-GUIDE.md` (руководство пользователя), `SPEC.md` (остров, по-французски), `INTEGRATIONS.md`, `AGENTS.md`, `VOICE.md`, `IPHONE.md` |
| `install.sh` | Установщик готовой сборки (однострочник из README) |
| `scripts/`, `apps/macos/scripts/` | Версия и выпуск; сборка бандла, проверка запуска, генерация иконок и звуков |

## Команды

```sh
brew install xcodegen                       # один раз; нужен Xcode 26+
for t in scripts/test-*.sh; do bash "$t"; done   # тесты (работают и на Xcode 16)
cd apps/macos && xcodegen generate          # после правки project.yml — и закоммитить результат
apps/macos/scripts/bundle.sh debug          # build/Luna.app под свою архитектуру
apps/macos/scripts/bundle.sh                # universal-бандл, подпись ad-hoc или LUNA_SIGN_IDENTITY
apps/macos/scripts/smoke.sh                 # бандл запускается и завершается
scripts/check-version.sh                    # версия согласована и описана в CHANGELOG.md
scripts/bump-version.sh minor               # поднять версию (minor | patch | номер) — на этапе слияния
```

Локальный Xcode 16 собирает тесты, но не приложение: код рассчитан на Swift 6.2 (строгая конкурентность, FoundationModels). Полную сборку проверяет CI на раннере `macos-26`.

## Инварианты

- **Swift 6, SwiftUI + AppKit, без сторонних зависимостей.** Персонаж рисуется кодом (`Canvas` + `TimelineView`) — никаких Rive, Lottie и картинок.
- **Секреты — в Keychain**, не на диске и не в git. Никакой телеметрии; сеть — только к сервисам, которые подключил пользователь.
- **Агентов не блокировать.** Хук отвечает сразу, если приложение не отвечает; `~/.claude/settings.json` и файлы хуков других CLI не перезаписываются: резервная копия с датой, слияние, diff — запись только после подтверждения человека.
- **Чат по подписке не смешивается с ключом молча.** Подпроцесс `claude` запускается только из `ClaudeCLIChat.swift`, без `--bare` и `--dangerously-skip-permissions`; из его окружения убираются `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` и метки родительской сессии (`CLIResolver.environment`). Без проекта — в служебной папке чата и с `--safe-mode`. Вопрос в проекте — в папке проекта без `--safe-mode`: CLAUDE.md, настройки, хуки и MCP проекта работают, как в обычном Claude Code; процесс помечен `LUNA_CHAT_SESSION`, его события хуков — не сессия агента, а запросы разрешений Luna не показывает и не разрешает (решает сам Claude Code по своим правилам). Под каждым ответом чата — подпись источника (и проект); между подпиской и ключом Luna сама не переключается.
- **Ни одно разрешение агента и ни одно письмо не уходят без явного клика.**
- **0 % CPU, когда остров скрыт.**
- **Bundle ID `dev.luna.Luna` не меняется:** на него завязаны Keychain, настройки и выданные разрешения macOS.
- **ID pill — контракт** (Keychain, UserDefaults, маршрутизация хуков): существующий ID не переименовывается. Payload-ключи `luna_agent`, `luna_kind` — контракт со сторонними агентами.
- **Существующие экраны не перерисовываются** без явной просьбы; новые следуют стилю приложения.
- **Ничего из LICENSE-ASSETS.md coucou в сборке нет:** имена «Coucou» и «Mochi», их иконка и звуки, медиа из `docs/media` и `design/captures`. Своё: персонаж — нарисован кодом в `LunaKit` (`BotEngine`, `LunaStill`), иконки — `apps/macos/scripts/render-icons.swift`, звуки — `render-sounds.py`. Идентификаторы в коде переименованы в Luna (LUNA-60): прежних имён в нём нет, кроме упоминаний источника.
- **Код взят из coucou один раз.** Коммит 0dffbaf записан в `LICENSE-COUCOU` как атрибуция по MIT. Дальше код ведётся в этом репозитории самостоятельно, имена — Luna; обновления из upstream не забираются.
- **Версия записана в двух местах:** `apps/macos/project.yml` и сгенерированный `apps/macos/Resources/Info.plist`. Меняет её только `scripts/bump-version.sh` — вместе с разделом в `CHANGELOG.md`.

Комментарии в коде, сообщения коммитов и тексты интерфейса для русской локали — на русском; код coucou и его комментарии остаются по-английски, переводить их не нужно.

## Как идёт работа

Задачи ведутся в Cadence Lab, проект `LUNA` (`https://sdlc.food-cart.ru/p/LUNA/board`). Роли и цикл живут там и приезжают агенту при захвате этапа; здесь — только то, что касается репозитория.

- **Эпик — это выпуск версии.** Эпик называется `Luna X.Y.Z` и копит задачи-кандидаты в этот выпуск: одна ветка, один PR в `main`, один выпуск. Открытый эпик следующей версии есть всегда: после выпуска сразу заводится эпик следующей (по умолчанию `minor`), пустой.
- **Задача — кандидат в ближайший выпуск.** Новая задача заводится в открытом эпике-версии и проходит свой цикл; эпик при этом остаётся в работе, пока человек не решит выпускать. Задач вне эпика не бывает. Кандидат, который к выпуску не готов, уходит в эпик следующей версии: родителя сменить нельзя, поэтому задача снимается (`cancel`) и заводится там заново со ссылкой на прежнюю.
- Ветка эпика — `clab/<ключ эпика>-<короткий-slug>` от свежего `origin/main`, PR — `<ключ эпика>: <название эпика>`, открывается **черновиком** (`gh pr create --draft`): пока задачи копятся, CI на пуши не идёт. На приёмке эпика PR переводится в ready (`gh pr ready`), и CI проверяет каждый пуш до слияния.
- Задача эпика — коммиты в его ветке; сообщение каждого начинается с `<ключ задачи>: `. Своего PR и своего выпуска у задачи нет. Проверки задачи — локальные (тесты, сборка, smoke); зелёный CI нужен только эпику перед слиянием.
- Ветка, PR и коммиты ищутся по ключам Cadence Lab: `git ls-remote --heads origin "clab/<ключ эпика>-*"`, `gh pr list --state all --head <ветка>`, `git log --grep="^<ключ задачи>: " origin/main..origin/<ветка>`.
- Рабочая копия задачи — `git worktree` в `.worktrees/<ключ задачи>` на локальной ветке `task/<ключ задачи>`, отправка — `git push origin HEAD:<ветка эпика>`; копия эпика (приёмка, слияние) — `.worktrees/<ключ эпика>`. Основная копия стоит на `main`.
- Запушенная история ветки не переписывается; свежий `main` и соседние задачи вливаются merge'ем. В `main` эпик попадает одним squash-коммитом `<ключ эпика>: <название>` со списком задач в теле.
- Слияние эпика — выпуск версии из его названия: перед слиянием версия поднимается в ветке (`scripts/bump-version.sh X.Y.Z`), остальное делает CI. Если к выпуску в эпике оказались только исправления, человек может выпустить его как `patch` — тогда эпик переименовывается.
- Коммиты заканчиваются трейлером `Co-Authored-By: <модель> <noreply@anthropic.com>`.

## CI и релизы

- `.github/workflows/ci.yml` — на PR не в статусе черновика (открытие, ready, каждый пуш), на push в `main` и вручную: проверка версии на Linux; тесты, debug-бандл и smoke на `macos-26` (только если изменение может затронуть приложение). На черновике PR задания пропускаются.
- `.github/workflows/release.yml` — коммит в `main` с версией, у которой ещё нет тега, — выпуск в релизы этого репозитория через `GITHUB_TOKEN`, секретов не нужно. Job'ы по порядку: `version` → `macos` (тесты, universal-бандл, smoke, архив `Luna-X.Y.Z-macos-universal.zip` и `checksums.txt`) → параллельно `verify` (матрица macos-15 и macos-26: `install.sh` из этого коммита ставит собранный архив через `LUNA_DOWNLOAD_BASE=file://…`, `codesign`, `lipo`, `smoke.sh`, `min_macos` = `LSMinimumSystemVersion`) и `draft` (`scripts/publish-release.sh`: черновик релиза с архивом, суммами и заметками из раздела `CHANGELOG.md`) → `publish` (черновик публикуется, этим ставится тег `vX.Y.Z`) → `downloads` (последний релиз — этот, архив скачивается, суммы сходятся). Ручной запуск Release (`gh workflow run release.yml --ref <ветка>`) — сухой прогон: `version`, `macos` и `verify`, без черновика, публикации и тега.
- Установщик — `install.sh` в корне: `curl -fsSL https://raw.githubusercontent.com/stepaKaziatko/luna-assistant/main/install.sh | sh`. Файлы релизов до v1.0.0 включительно он берёт из архива `stepaKaziatko/luna-releases`, новее — из релизов этого репозитория; проверяется `scripts/test-install.sh`, публикация — `scripts/test-publish-release.sh`. Руководство пользователя — `docs/USER-GUIDE.md`.
- Версия: эпик-версия с новой возможностью — `minor`, только с исправлениями — `patch`. Служебные правки (документация, CI, тесты) идут кандидатами в открытый эпик-версию; прямой коммит в `main` без версии — только по решению человека.
- Заметные пользователю изменения копятся в разделе «Дальше» файла `CHANGELOG.md`; `scripts/bump-version.sh` отдаёт его новой версии, и раздел уходит в заметки публичного релиза.
- Упавший выпуск повторяется перезапуском прогона (`gh run rerun <id> --failed`) или следующим коммитом той же версии: тег ставится последним шагом, публикацией черновика. Упала проверка установки — релиз остаётся черновиком, тега нет; повторный `draft` заменяет файлы, заметки и коммит черновика.
- `stepaKaziatko/luna-releases` — архив: там релизы v0.2–v1.0 и прежний адрес установщика, который ставит релизы этого репозитория. После выпуска 1.1.0 он архивируется, больше не правится и в область задач не добавляется.
