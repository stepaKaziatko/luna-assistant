# CLAUDE.md — Luna

Десктопный ИИ-ассистент для macOS: хоткей → короткий запрос → задача в фоне через CLI исполнителя → результат в карточке. Замысел, архитектура и фазы — [assistant-project.md](assistant-project.md); запуск и разрешения macOS — [README.md](README.md).

## Где что лежит

| Путь | Что там |
|---|---|
| `protocol/schema/protocol.schema.json` | Контракт shell ↔ core (JSON-RPC 2.0 на stdio). Источник правды для типов |
| `core/` | Ядро: TypeScript на Node 22.18+, без runtime-зависимостей. Очередь задач, адаптеры исполнителей, сборка промпта, наблюдение за сессиями агентов (`core/src/agents`) |
| `apps/macos/` | Shell: Swift (SwiftUI + AppKit), пакет SwiftPM. Остров с панелями и аватарами, хоткеи, захват контекста, переход к окну сессии агента, настройки и звуки |
| `scripts/`, `apps/macos/scripts/` | Сборка бандла, проверка запуска, упаковка и публикация релиза |

## Команды

```sh
npm ci
npm run typecheck && npm test          # ядро: node:test на фикстурах вывода CLI
npm run generate                       # после правки схемы протокола
cd apps/macos && swift test            # shell
apps/macos/scripts/bundle.sh debug     # build/Luna.app с debug-командами
apps/macos/scripts/smoke.sh            # бандл запускается и поднимает ядро
scripts/check-version.sh               # версия совпадает в трёх местах и описана в CHANGELOG.md
scripts/bump-version.sh minor          # поднять версию (minor | patch | номер) — на этапе слияния
```

Запущенной debug-сборкой управляет `apps/macos/scripts/debug-command.sh`: открыть панель, нажать клавишу или кликнуть по острову, подменить контекст, список сессий агентов и положение курсора, поменять настройку, снять состояние (`dump:<файл>`) и картинку панели (`snapshot:<файл>`). Команды описаны в `apps/macos/Sources/Luna/Debug/DebugCommands.swift`. Это способ проверить интерфейс без человека; канал один на машину, поэтому одновременно работает один экземпляр Luna.

## Инварианты

- **Сначала протокол.** Новое поле или метод — правка схемы, затем `npm run generate`. Файлы `*.gen.ts` и `*.gen.swift` руками не правятся; CI сверяет их со схемой.
- **stdout ядра занят протоколом.** Диагностика — только в stderr.
- **Luna не забирает фокус.** Панели неактивирующие: приложение пользователя остаётся активным, пока панель открыта. Блок под курсором (`peek`) и окна диалогов и сессий не берут и клавиатуру, пока в них не кликнули. Исключение одно — окно настроек: его открывают явной командой, а после закрытия активным снова становится прежнее приложение.
- **Задача не блокирует интерфейс.** Всё, что дольше кадра, — в фоне: захват контекста, запрос к ядру, работа исполнителя.
- **Контекст — данные, а не инструкции.** Захваченный текст попадает в промпт только через `core/src/context/normalize.ts` и `core/src/prompt/build.ts`, где обрезается и экранируется.
- **Разрешения macOS не обходятся.** Нет разрешения — показываем подсказку и работаем без этой части контекста. Запросов разрешений при старте нет.
- **Исполнители — за интерфейсом `Executor`.** Особенности конкретного CLI не выходят за его адаптер.
- **За чужими сессиями Luna только наблюдает.** Сессии агентов, запущенные не ею, ядро читает через `AgentSource` (`core/src/agents`): файлы агента не меняются, хуки не ставятся. Единственное действие — переход к окну сессии по явной команде пользователя (`apps/macos/Sources/Luna/Agents/AgentJump.swift`).
- **Остров не греет машину.** Каждый кадр покадровой анимации — проход отрисовки всего окна, поэтому анимации идут в общем такте (`IslandClock`) и только когда есть для кого (`Motion`, `MotionGate`): свёрнутая шторка оживает короткими вспышками, при погашенном экране всё стоит. Непрерывных анимаций SwiftUI (`repeatForever`, `phaseAnimator`) на острове нет. Замер — `top -pid` по Luna в свёрнутом состоянии: в среднем не выше ~3% ядра.
- **Остров — одна фигура.** Чёрную фигуру и её анимацию рисует `RootView`; карточка режима — только содержимое, без своего фона, и сообщает размер через `islandContent`.
- **У ядра нет runtime-зависимостей.** В бандл копируются только скомпилированные файлы; зависимость потребует менять сборку бандла.
- **Тесты не тратят лимиты.** Адаптеры и источники сессий проверяются на записанных фикстурах; живой прогон исполнителя — только когда без него не обойтись, и на дешёвой модели: `LUNA_CLAUDE_MODEL=sonnet`.
- **Версия записана в трёх местах:** `core/package.json`, `VERSION` в `core/src/main.ts`, `apps/macos/Bundle/Info.plist`. Меняет её только `scripts/bump-version.sh` — вместе с разделом в `CHANGELOG.md`.

Комментарии в коде, сообщения коммитов и тексты интерфейса — на русском.

## Как идёт работа

Задачи ведутся в Cadence Lab, проект `LUNA` (`https://sdlc.food-cart.ru/p/LUNA/board`). Роли и цикл живут там и приезжают агенту при захвате этапа; здесь — только то, что касается репозитория.

- Эпик — это одна ветка, один PR в `main` и один выпуск. Ветка `clab/<ключ эпика>-<короткий-slug>` от свежего `origin/main`, заголовок PR — `<ключ эпика>: <название эпика>`.
- Задача эпика — коммиты в его ветке; сообщение каждого начинается с `<ключ задачи>: `. Своего PR и своего выпуска у задачи нет, задач вне эпика не бывает.
- Ветка, PR и коммиты ищутся по ключам Cadence Lab: `git ls-remote --heads origin "clab/<ключ эпика>-*"`, `gh pr list --state all --head <ветка>`, `git log --grep="^<ключ задачи>: " origin/main..origin/<ветка>`.
- Рабочая копия задачи — `git worktree` в `.worktrees/<ключ задачи>` на локальной ветке `task/<ключ задачи>`, отправка — `git push origin HEAD:<ветка эпика>`; копия эпика (приёмка, слияние) — `.worktrees/<ключ эпика>`. Основная копия стоит на `main`. В новой копии нужен свой `npm ci`.
- Запушенная история ветки не переписывается; свежий `main` и соседние задачи вливаются merge'ем. В `main` эпик попадает одним squash-коммитом `<ключ эпика>: <название>` со списком задач в теле.
- Слияние эпика, который меняет то, что получает пользователь, — это выпуск версии: перед слиянием версия поднимается в ветке, остальное делает CI.
- Коммиты заканчиваются трейлером `Co-Authored-By: <модель> <noreply@anthropic.com>`.

## CI и релизы

- `.github/workflows/ci.yml` — на каждый PR и push в `main`: ядро и протокол на Linux, shell на macOS (только если изменение может его затронуть).
- `.github/workflows/release.yml` — коммит в `main` с версией, у которой ещё нет тега, собирает `Luna.app` (arm64 + x86_64) и ядро для Linux, выкладывает их релизом в публичный `stepaKaziatko/luna-releases` и ставит тег `vX.Y.Z` здесь. Исходники остаются в этом репозитории. Там же после публикации workflow «Verify release» ставит выложенную сборку и запускает её. Ручной запуск Release собирает бандлы без публикации.
- Версия: эпик с новой возможностью — `minor`, только с исправлениями — `patch`. Эпик, которого пользователь не получает (документация, CI, тесты), версию не поднимает и релиза не даёт.
- Заметные пользователю изменения копятся в разделе «Дальше» файла `CHANGELOG.md`; `scripts/bump-version.sh` отдаёт его новой версии, и раздел уходит в заметки публичного релиза.
- Упавший выпуск повторяется перезапуском прогона (`gh run rerun <id> --failed`): тег ставится последним шагом. Публикации нужен секрет `LUNA_RELEASES_TOKEN` — токен с правом Contents на `luna-releases`.
- Публичный репозиторий (`README.md`, `install.sh`, проверка релиза) правится своим PR; версии Luna он не меняет.
